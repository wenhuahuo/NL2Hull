# Jev-like 模型驱动的船型 NURBS/FFD 研究计划

## 1. 核心结论
1. 将 Jev-like 模型作为船型自由变形的**离散决策层**，不让模型直接生成大量 NURBS 控制点数值。
2. 构建船型自由变形的结构化动作表示和自然语言数据集。

建议的论文主题为：

> 面向 NURBS 船体自由变形的约束感知类型化决策框架，实现自然语言到船型变形动作的可靠映射。

英文表述可采用：

> We propose a constraint-aware typed decision framework for natural-language-driven free-form deformation of NURBS ship hulls.

---

## 2. Jev 公开信息核查

TypeSafe AI 官方将 Jev 描述为面向软件决策的模型：

- 输入状态 `state` 和类型化问题；
- 输出结构化决策、概率和置信度；
- 支持三类问题：
  - `choice`：从候选集合中选择一个；
  - `score`：在有序等级上评分；
  - `noul`：布尔判断；
- 多个问题可以针对同一个状态并行计算；
- 官方称其使用 Reinforcement Learning for Calibrated Decisions（RLCD，校准决策强化学习）；
- 官方模型以 API/early access 形式提供，权重没有公开；
- 官方尚未公开完整架构、参数规模、训练数据、RLCD 损失函数和奖励构造。

官方资料：

- [Introducing System One Models & Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- [AI Primer](https://docs.typesafe.ai/introduction/machine-learning-primer)
- [State](https://docs.typesafe.ai/concepts/state)

### 可关注的开源项目

- [Kev](https://github.com/jaredpalmer/kev)：基于 Qwen 系列，支持训练和本地运行；
- [OpenJev](https://github.com/razorback16/openjev)：开源模型上的 Jev 风格决策接口；
- [NanoJev](https://github.com/tianyucodings/nanojev)：轻量 Jev 风格实现；
- [Jevlike](https://github.com/vinnylarouge/jevlike)：社区逆向构建的 Jev-like 架构；
- [TypeSafe 官方 Python 适配器](https://github.com/typesafe-ai/system-one-adapter-python)：用于包装其他模型，不包含 Jev 权重。

论文中必须区分官方 Jev、Jev-like 模型、Jev-style 接口和普通大模型结构化输出。

## 3. 当前项目状态与下一步

当前项目已经实现或具备以下基础：

- STL 船体读取；
- 多层水线提取；
- 每条水线拟合 8 控制点、三次有理 NURBS；
- 艏艉轮廓单独拟合；
- 输出 `source_parameters.json`；
- 船体重建和误差验证。

当前项目的主要任务仍是几何重建，代码中还没有明确的 FFD 动作层。因此不宜立即开始语言模型微调，应先建立稳定的船型变形接口：

```text
当前船型参数
    ↓
变形动作 Δp
    ↓
NURBS / FFD 参数更新
    ↓
几何重建
    ↓
约束检查与性能评价
```

建议定义统一的动作对象：

```json
{
  "region": "bow",
  "operation": "increase_flare",
  "magnitude_level": 2,
  "magnitude_value": 0.04,
  "longitudinal_extent": [0.65, 1.0],
  "vertical_extent": [0.2, 0.9],
  "symmetry": true,
  "constraints": {
    "preserve_displacement": true,
    "max_curvature_change": 0.15
  }
}
```

自然语言模型负责产生或选择动作对象，几何程序负责执行动作。

## 4. Jev-like 模型与船型 FFD 的适配

### 4.1 使用船型变形动作基元

直接让模型输出大量控制点偏移量会导致输出空间过大、数值不稳定、尺度不统一，并容易产生自交、尖点和不光顺曲面。

建议先定义具有船舶工程含义的变形基元：

| 类别 | 示例 |
|---|---|
| 区域 | 艏部、艉部、球鼻艏、中体、甲板、舭部 |
| 方向 | 外扩、内收、上抬、下压、前移、后移 |
| 形状操作 | 增加艏部丰满度、减小艉部丰满度、增加外飘、改变球鼻艏长度 |
| 影响范围 | 局部、中等、全局 |
| 变形强度 | 极小、小、中、大、极大 |
| 约束 | 保持排水量、保持吃水、保持对称、保持甲板线 |

对于用户输入精确数值的情况，就由模型直接输出精确数值，这部分内容也需要考虑进训练数据中

同时训练数据集要包含多步编辑的数据，包含连续修改，修改回退内容，避免将此类内容全部交由工程实现来约束

### 4.2 映射到三类问题

#### `choice`

适合互斥选择：

```text
变形主要发生在哪个区域？
艏部 / 艉部 / 球鼻艏 / 中体 / 舭部 / 甲板
```

```text
变形类型是什么？
增加丰满度 / 增加外飘 / 改变球鼻艏长度 / 减小艉部丰满度
```

#### `noul`

适合独立布尔判断：

```text
是否需要保持排水量？
是否需要保持左右对称？
是否存在几何自交风险？
```

如果一个请求可以同时涉及多个区域，应使用多个 `noul`，不要强制使用一个互斥的 `choice`。

#### `score`

适合离散强度，不适合直接表示任意连续实数：

```text
0 = 无变化
1 = 很小
2 = 小
3 = 中等
4 = 大
5 = 很大
```

程序将等级映射为归一化物理量：

```python
delta_breadth = magnitude_table[level] * beam
delta_x = longitudinal_table[level] * length
delta_z = vertical_table[level] * draft
```

## 5. 推荐系统架构

```text
用户自然语言
      ↓
Jev-like 决策模型
      ├── 区域选择
      ├── 变形类型
      ├── 变形等级
      ├── 约束判断
      └── 置信度
      ↓
FFD / NURBS 动作解码器
      ↓
船体重建
      ↓
几何约束检查
      ├── 自交检查
      ├── 曲率连续性
      ├── 排水量
      ├── 吃水
      └── 船体尺度
      ↓
水动力快速代理模型或 CFD
      ↓
接受、修复、回退或请求人工确认
```

Jev-like 模型适合作为中间决策层，不能独立承担开放式自然语言理解、连续参数计算和几何执行。

## 6. 数据集构建方案

### 6.1 程序生成的几何动作数据

程序化数据应作为主数据来源：

```text
原始 NURBS / FFD 参数
→ 随机选择区域
→ 随机选择变形基元
→ 随机选择强度和范围
→ 生成新船体
→ 几何合法性检查
→ 计算几何变化和水动力指标
```

这部分标签由程序产生，具有可复现性。

### 6.2 大模型生成自然语言表达

针对同一结构化动作生成多种表达：

- “把船艏做得更丰满一些”；
- “增加前体排水量”；
- “让艏部线型更加外飘”；
- “球鼻艏向前延伸，但不要改变设计吃水”。

可生成同义表达、中英文表达、模糊表达、带单位的精确表达、多轮修改指令和含约束的复杂请求。

### 6.3 专家或高质量模型校验

需要对部分数据进行人工或高质量模型复核：

- 用户意图；
- 变形区域；
- 参数含义；
- 船舶设计合理性；
- 几何变形结果；
- 约束是否满足。

---

## 7. 数据规模建议

第一篇论文可以采用以下规模：

- 5,000–10,000 个基础船型状态；
- 每个状态生成 5–10 个变形动作；
- 30,000–100,000 个结构化动作样本；
- 每个动作生成 3–5 条自然语言表达；
- 100,000–500,000 条语言—动作样本；
- 2,000–5,000 条独立测试样本。

训练集和测试集应按船型家族划分，避免同一船型的小扰动同时出现在训练集和测试集。

应重点报告：

- 变形区域分布；
- 变形强度分布；
- 单动作和组合动作比例；
- 语言表达多样性；
- 未见表达测试；
- 超出可行范围的请求；
- 保持排水量、吃水等工程约束。

数据总量不能替代船型家族隔离和分布覆盖。

## 8. 对比实验设计

建议设置以下基线：

1. 规则解析器；
2. 通用大模型 + 提示词；
3. 原生 Jev；
4. 零样本 Jev-like；
5. 微调 Jev-like；
6. 传统参数优化方法；
7. 不带几何约束的模型。

需要比较：

- 区域分类准确率；
- 变形类型准确率；
- 强度等级误差；
- 约束判断准确率；
- FFD 后几何合法率；
- 控制点或参数误差；
- 排水量、吃水等指标变化；
- 推理延迟；
- 推理成本；
- 人工确认率。

通用大模型基线必须固定模型版本、提示词、schema、解码器、约束修复器、温度和重试策略。

## 9. 论文贡献建议

建议将贡献拆分为四点：

1. **船型nurbs表示与FFD接口**：统一表示方法和变形接口；
2. **提出自然语言驱动的船型FFD决策模型**：引入jev-like模型到船舶设计
2. **船型 FFD 决策数据集**：程序生成几何真值，大模型扩展自然语言表达；

## 10. 实施路线

### 阶段 1：几何动作接口

- 明确定义 NURBS / FFD 参数；
- 实现变形基元；
- 实现归一化参数；
- 输出统一动作 JSON。

### 阶段 2：程序化数据集

- 生成基础船型；
- 生成合法和非法变形；
- 记录参数变化和约束结果；
- 生成水动力代理标签。

### 阶段 3：自然语言数据

- 使用 GPT、Claude、Kimi 等模型生成表达；
- 自动校验语言样本；
- 人工抽检；
- 构造未见语言测试集。

### 阶段 4：训练 Jev-like 模型

- 先训练离散决策；
- 再加入多动作和工程约束；

### 阶段 5：论文实验

```text
规则方法
vs 通用大模型
vs 原生 Jev
vs 零样本 Jev-like
vs 微调 Jev-like
```

核心评价指标为：

```text
决策准确性
+ 几何可行率
+ 变形参数误差
+ 约束满足率
+ 概率校准
+ 推理延迟
+ 推理成本
```

最优先的工作是设计稳定的船型 FFD 动作空间，再选择和微调模型。当前阶段直接围绕训练 Jev 展开会过早，论文核心应落在船型 FFD 动作表示、可验证数据集和约束闭环上。
